# メモ・ブロックの非破壊読込と保存保護

## 背景と判断変更（2026-10-19 JST）
PR #32後のmain `8c861b786b2972468398b05d8732ee00740615d9`では、不正なブロック配列をundefinedへ縮退し、本文Markdownを残す方針だった。不正メモはfilterで除外していた。これは既存storageテストにも明示されていたが、成功読込後の自動保存で元構造が失われる経路が成立する。実ユーザーデータの損失を確認したものではない。

新方針は構造を読めない場合の全体保護停止。メモ、登録式、履歴、設定はlocalStorageの同じキーへ一括保存されるため、正常な兄弟メモを選ぶだけでは保存を再開できない。ノート単位の部分編集は今回対象外。既存の復旧バナーと原JSONコピーを再利用する。

## 読込契約
- `version: 1`の形式は変更しない。blocksがない旧本文メモと空配列は正常。
- メモIDはnotes内、ブロックIDは同じメモ内で非空・一意。IDを自動修復/再採番しない。
- 未知note type/schemaVersion、未知block type、必須項目型不正、非有限結果、未知evaluationModeを拒否する。
- 空タイトル/本文/日時文字列は以前同様許可。文字列日時の意味検証や式の再評価はしない。計算エラーを含む正当なブロック（result:null）も保持する。
- 正常な既知メモ/ブロックの追加フィールドはspreadで保持する。未知ブロックの意味を推測して編集可能にはしない。
- 失敗時は`StorageLoadResult.error.raw`に読んだ原JSONをそのまま保持。書き換えない。同時に保存領域にも元データを残す。別バックアップキーは作らない。

## 保存境界とUI
- 自動保存は既存storageStatus readyだけ。失敗読込時はworkspaceをinertにし、電卓の全体キーボード操作とメモ保存callbackも停止。ヘッダーのテーマ/説明閲覧は使えるが保存はしない。
- `saveData`は呼出元に関係なく保存先の現行データを再検査し、候補のnotesをJSON化前に検査、JSON化後のデータもload契約で検査してからsetItemする。これにより画面以外の通常保存経路も不明データを上書きしない。
- 保存直前に別タブ等で不正データへ変わった場合も通常保存は拒否する。画面は次の保存失敗で復旧表示へ移行する。
- 既存の「保存データを初期化」→破棄警告→「初期化する」は明示的な破棄操作として維持。通常saveのbypass optionを設けず、専用`resetStoredData(expectedRaw)`だけが初期値を保存する。確認中に保存内容が変わったら初期化も拒否する。自動初期化しない。
- 修復した正常データを再読込すれば保存再開。未対応データを含んだままの部分編集・自動修復・新import UIはない。

## 境界/残るリスク
- localStorageのgetItem→setItemは他タブに対する原子的比較交換ではない。完全な多タブ競合解決・悪意ある外部書換えへの保証は今回の範囲外。
- この保護はこの版以降のreader/writerに適用。旧版アプリへ戻せば旧縮退動作が再びある。戻し方は作業PRのrevertだが安全修正自体を取り消すことになる。
- ブラウザによる保存領域消去、容量超過、プライベートモード、長期保持は別の制約。原JSONのコピーは利用者による退避手段であり、外部バックアップを自動生成しない。
- historyの従来filter/settings正規化の全面変更は行わない。構造検証であり、保存計算結果と式の数学的一致を保証する検査ではない。
- iPhone Safari実機、OSキーボード/IME、支援技術、OS文字拡大/長期保存は未検証。Playwright WebKitは代替エンジン検証。

## 検証
単体は未知/混在/不正/重複・空ID/旧データ/空blocks/非有限値/追加フィールド/保存先変化/復旧後保存/初期化原文照合/保存領域getter失敗を確認する。GUIは既存6条件に保護表示、テーマ・キー操作、元JSONコピー呼出値（合成clipboard sink、OS clipboard自体は未検証）、初期化cancel、reload原文一致、正常データへの修復後編集・保存、明示初期化を追加。保存データとブラウザcontextは合成のみ。CIのexact SHAと結果はPR Checks・LOGを参照。

- 日時文字列の妥当性は今回のブロック保護の対象外。空/不正な日時は旧版同様に読込を許容するが、既存の日付表示が例外になる場合がある（GUI用正常fixtureの空日時で確認）。全ての不正メモ内容を安全に描画する保証ではない。日時検証/表示fallbackは別課題。

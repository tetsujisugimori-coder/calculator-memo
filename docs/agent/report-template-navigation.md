# 数学レポートのテンプレートと章一覧（Issue #72）

## 調査と設計

基点 main は PR #70 の merge `bdadd3dede1f15857fc0217bfe09147e46ba9666`。PR #71 は未マージで依存しない。既存の `FormulaReportModal` は新規レポートへ5章の本文を初期設定し、`MarkdownContent` 内の安全な独自サブセット parser が表示を担当していた。既存保存経路は `saveFormulaReport`、共有ロックと原本比較、checked 読戻しを使う。確認備考は確認履歴の optional remarks、履歴20件・全体1MBである。

第一希望の「既存本文を保持して追加」を採用する。標準を概要／定義・前提条件／導出・証明／計算例／由緒・歴史／参考文献・出典の6章と簡潔な記入案内にする。新規時の初期本文という既存動作は維持。既存レポートは勝手に変更せず、編集画面の明示ボタンで末尾へ追加する。章名・順序・内容は普通のMarkdownとして自由に編集でき、全章記入の義務や内容の自動生成はない。

## 取消と保護

React controlled textarea へのプログラム挿入はブラウザ標準Undoの一貫性を保証できない。このため位置を事前説明し、直前の追加専用取消を備える。取消は追加後の本文が一致するときだけ可能。その後の本文編集または保存成功で取消スナップショットを破棄し、後続編集を失わせない。連続追加の取消は直前の1回だけ。通常の文字入力のUndo動作はブラウザ依存であり、新しい汎用履歴機構は導入しない。

追加で100,000文字を超える場合は追加前に停止し、本文を保持する。既存保存時の全体1MB上限・履歴20件・未知フィールド・未知形式・競合・再取得失敗・読戻しの保護は変更しない。保存中は追加／取消／章移動を禁止する。追加や移動は保存・明示確認・再計算を呼ばない。未保存本文を現在確認済みの根拠と扱わず、従来の dirty と assessment を使用する。確認備考と過去履歴は変更しない。

## 共通解析と移動

`MarkdownContent` の既存 block parser を `lib/markdown-blocks.ts` へ抽出し、表示と章一覧で共用する。新しいMarkdownエンジン・依存は追加しない。ATX見出し（行頭 #〜###### と空白）の既存表示範囲を基準とし、Setext・入れ子リストや引用内の見出し等は対象外。バッククォート／チルダの3文字以上のコードフェンス（最大3空白字下げ、同じ記号で開始以上の長さの終了）内は見出しにしない。独立数式内も除外。HTMLは従来どおり文字列で、KaTeXと安全なリンク表示を再利用する。

見出しは現在本文の出現順IDを持ち、同名を区別する。追加・削除・並べ替えで再計算する表示専用IDで、安定した保存識別子ではない。元本文のUTF-16位置を取得し、編集時はtextareaの改行正規化に合わせた該当行を選択する。プレビュー時は同じIDの見出しへフォーカスを移す。生Markdownの見出し文字列を一覧に使うため、数式・強調等の記法自体が一覧では見える。プレビューの数式表示とは意図的に区別する。

章一覧は折りたたみ可能な縦リスト。H1〜H6を文字で示し、同名見出しは順序で区別できる。長い章名は折り返し、リストに高さ上限を設ける。PC・モバイルとも同じ控えめな構成。ネイティブdetails/buttonと明示フォーカスでキーボード／読み上げを支援する。本文上限を超える場合はプレビュー同様に解析を停止し、本文は切り捨てない。

## 保存形式・戻し方・将来

保存形式・version・確認条件・計算処理の変更なし。生成されるものは通常の本文だけなので本変更をrevertしても本文は旧表示部品で読める。ただしPR #70のremarksを含む原本をそれ以前へ戻す際は従来どおり原本JSONを退避し、未知キーを削除して回避しない。外部アクセス、Memo-Nexus通信、証明自動生成、変更理由の推測は追加しない。将来の証明／由緒レポートも自由記述と明示確認を基盤とし、章の充足や数学的正しさを機械認定しない。

## 検証の限界

GitHub Actionsとローカル検証の成否はLOGとPRの対象SHAを参照。自動WebKit mobile emulation は実機iPhone Safariではなく、VoiceOver・ソフトキーボードは未検証。ブラウザネイティブUndoは保証対象外であり、専用取消の保全性を試験する。

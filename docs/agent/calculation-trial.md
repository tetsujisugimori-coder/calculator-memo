# 計算メモの試算・差分プレビュー

2026-10-20 (JST)。基点 main `1d43eccb49bdc81177d4d6c122290d455d174b71`（PR #41 merge）。

## 現状と最小分離

従来の `recalculateReferenceMemo` は評価結果の配列を生成するだけで、editor の `onChange` が編集 draft へ反映していた。永続保存は `PlainNoteModal` の「保存する」である。今回、その評価本体を `evaluateReferenceMemo` として共有し、途中の実評価だけを `observations` に追加する。従来入口は元と同じ4項目だけを返し、数値・順序・preflight/旧変数/ID失敗停止・最初のエラー・rollbackを維持する。新しい演算器や解析器は作らない。

失敗しても途中の観測値を表示できるが、`evaluation.blocks` は従来のrollbackされた配列である。観測値を確定値として混ぜない。legacyは最後まで実行し、失敗再代入後も旧scopeを維持する。IDはcanonical ready順で最初の失敗まで。未試行は「変化なし」や成功ではない。

## 操作と保存境界

- 「試算する」は現在の編集 snapshot を明示的に評価し、純派生の試算カードを作る。editor の `onChange`、保存callback、storageを呼ばない。入力変更による自動試算はない。
- 「結果を反映」は全成功、同じ対象・世代・入力、再評価との一致を確認してから既存の一括確定と同じ編集draft反映をする。部分反映はしない。成功後は一時試算を除去し、残る「試算する」へfocusを戻す。
- 永続保存はどちらも既存の「保存する」のみ。試算中に通常保存しても、未反映の観測値は保存されない。取消・modal終了では試算を破棄する。
- 既存「メモ全体を再計算」は全成功時にdraftへ即時反映し、失敗時のstale/attemptError処理も従来どおり。

導線はID参照標準の**手動計算メモ**に追加する。そこに混在する旧変数・旧四則も同じ評価計画で扱う。旧自動計算メモの入力時/保存時の評価意味論を無断で変えないため、その旧モードへ試算ボタンを追加していない。既存の明示的な参照モード切替で手動メモになれば試算できる。通常電卓・履歴・登録式・単独計算メモは変更しない。

## 比較・証拠状態

比較対象は編集中メモが現在保持している結果で、必ずしも永続保存済みではない。保存済み/保持中error、値なし、旧結果・全体未確定を分け、以前のbaseline不明は既存i診断で明示する。元の保存errorを現在式の試算失敗と断定しない。

新旧とも成功した有限numberだけを比較し、内部値の厳密な `===` と差の減算を使う。表示用の丸め文字列は判定に使わない。差分は `String(number)` で小さい差も指数表示でき、内部値も併記する。IEEE754の浮動小数点差であり数学的厳密差ではない。非有限差は比較不可。未知の前値、失敗、未試行は差分0にしない。

変更元/影響候補/通常/不明、構造確認/今回評価/保存記録は `buildCalculationStatus` と `CalculationStatusDetails` を共有する。試算用coverageは「未反映」とし、一括確定済みと呼ばない。複数の既知原因と未試行の範囲を残し、iから既存安定ID移動を利用する。Mermaidとアプリ内図に試算差分を重畳しない。

## 失効と反映直前の確認

`TrialContext` はメモ識別・元メモrevision・編集タイトルを含むscope、世代、ブロック全体のexact snapshotを持つ。元メモrevisionには編集開始時のinitialだけでなく親の現在data.notes対象原本も渡し、draftを置き換えない原本更新でも失効する。snapshotは型付き値を直列化し、undefined/null/-0および未知fieldも区別する。hashや永続cacheではない。

式/参照/旧変数/追加削除/並べ替え/元データ/対象メモが変わると失効する。A→B→Aに戻しても世代が違うため再試算が必要。値が同じ新しいブロック配列や文章・付随情報だけの変更も保守的に失効させる。これは影響解析上の「変更元」を過大判定することとは別である。

試算はPromise境界を持つが、数値エンジンは従来の同期処理。request番号と最新の入力・scope・世代・mountを確認し、古い完了/失敗が新しい試算や画面を上書きしない。Web Worker等の並列計算は導入していない。反映直前にも最新snapshotを検査して既存エンジンで再評価し、試算候補配列とのexact一致を確認する。preview payloadの無条件コピーはしない。未知fieldは最新入力を通す既存mergeによって保持する。

計算メモmodalは対象IDをReact keyに使い、別メモ切替でローカルdraft/試算を混ぜない。非破壊読込保護の保存入口と既存JSON/versionは変更しない。

## 検証と制約

既存602テストの期待値を変更せず、純粋API・UIの非破壊/保存callback0/試算と通常計算一致/内部値差/失敗scope/未試行/全件反映/失効/非同期競合/JSON/未知fieldを追加。独立レビューでapply後focus喪失とA→B→Aの失効表示不一致を見つけ、修正と独立回帰を追加した。さらに取消済みの非同期試算がA→B→A後に処理中表示を再浮上させるケースを修正前に再現し、pending表示にも世代照合を加えて解消した。件数、GUI全6条件、最終HEAD/CIはLOG/PRを参照。

全件成功のみの確定は、部分結果を保存して依存元・下流の世代が混在することを防ぐ既存契約として維持する。永続trial履歴/部分確定/自動試算/差分図/実iPhone Safari・OSキーボード/VoiceOver実機受入は対象外または未検証。将来の表示が利用できる構造化rowsは提供するが、将来機能自体は実装しない。

# レポート全体の根拠点検

## 着手と再利用方針（2026-10-25 JST、Issue #84）
PR #83 は merge 済み。clean な main 163e31db から専用枝を開始する。既存 Markdown parser、strict difference envelope scanner、snapshot validator、保存原本照合、RecordInfo / BlockInfo / 差分出典 dialog / 引用比較、Modal の focus と Escape を再利用する。

第一希望は本文を一度解析して出現単位の一時 inventory を作り、独立した明示取得結果を全項目へ適用する方式。本文編集と出典状態を分離し、壊れた領域以後を推測で列挙しない。既存のレポート編集・個別引用表示の取得結果を点検済みとして流用しない。次善策の既存状態一覧の単純連結は、本文順・取得世代・本文編集と出典状態の分離を満たさないため不採用。新規保存形式・汎用基盤・依存追加は不要。

## 契約
- 現在表示本文だけを対象とする。編集中の本文は明示する。認識可能な出現数を分母とし、種類や出典の個数で重複加算しない。複数の出典状態は行内で個別表示し、見直し対象は行単位の OR で集計する。
- 初期未照合、明示照合で一度だけ保存原本を取得する。取得日時は観測日時であり確認日時ではない。本文/レポートID/登録式/関連付け/原本世代変更は照合・詳細・位置を失効させる。取得失敗時は古い成功を残さない。
- strict scanner の完全一致マーカー、閉鎖、構造検証、同一ID契約を維持。未知/将来/破損/重複/入れ子で曖昧なら EOF まで回復せず不完全集計を表示。通常コード内文字列は解析しない。マーカー全削除後の任意文章の由来は推測しない。
- 閲覧・照合・絞り込み・本文移動は保存/再計算/確認/自動修復を呼ばない。本文・両snapshot・原本・確認履歴は不変。位置移動だけは明示操作で編集欄の選択を変更する。
- 原本一致、本文対応、明示確認、数学的正しさは別概念。全件一致でも確認済みや証明成立へ昇格しない。0件は完了ではない。保存schema/version/容量・挿入/専用取消は変更しない。

## 制約
壊れた領域で隠れた項目数は不明。安全な対応位置を確定できなければ移動しない。原本更新の検知は既存アプリ通知と storage event の範囲で、任意外部 writer に対する原子的整合性や常時最新性を保証しない。実機 Safari / VoiceOver / OS ソフトキーボードは自動ブラウザと別条件。

## 実装上の失効と詳細
`FormulaReportAudit` は本文・登録式定義・レポート識別/保存署名・関連付け・確定保存世代の context を親が変えた時に破棄する。未保存本文は保持する。同一タブの保存成功は既存 confirmedSerialized を伝播し、他タブは storage event で未照合へ戻す。取得が失敗した場合は今回の失敗だけを表示し、以前の成功を残さない。未取得/失敗時のリンク状態は不明であって解除ではない。

本文移動は既存章移動の textarea 選択・スクロール処理を共用する。UTF-16位置は textarea の改行正規化へ変換し、遅延描画までにcontextまたはstorage通知epochが変わったら移動しない。繰返し通知もbooleanでまとめず失効させる。閲覧位置だけを変更し、本文と保存原本は変更しない。本文対応が不明な壊れた項目は移動不可、検証可能な固定snapshotは現在原本欠落時も既存詳細で表示できる。

独立レビューでは未取得リンクの不存在誤表示と遅延位置移動の失効漏れを検出し、両方を修正した。テスト・実CIの結果と未検証事項はLOG/PRを参照する。新しい永続情報・migrationはなく、rollbackはコードrevertのみ。

# 確認時の任意備考（Issue #69）

## 調査と設計

PR #68 がマージされた main `07f7e259c621685a30b587c957259da876bddbe9` を基準とする。既存の確認は `FormulaReportConfirmation`、保存候補生成は `saveFormulaReport`、安全な確定は `persistFormulaReport` の共有ロック・期待 raw・`saveDataChecked` の読戻しで行われる。タイムラインは保存原本だけを投影し、`formulaReportAssessment` が式・本文・根拠照合を担う。

第一希望を採用し、既存 version 1 の確認レコードに optional `remarks: string` を追加する。新規の明示確認では空欄も `""` を記録する。旧履歴の項目欠落は保持し「備考の記録なし」、空文字は「備考は入力されていません」と表示する。過去の配列順・ID・日時・内容を移行、再生成、後付けしない。version 更新や別イベント台帳は不要。別領域への保存は、確認トランザクションと関連付けが二重になるため採用しない。

備考は利用者の確認時の申告である。変更日時・変更理由の客観的記録、当時の自動判定結果、現在の承認、数学的正しさを意味しない。現在状態の照合条件に備考を加えない。厳格な validator は今回のキーだけを追加認識し、それ以外の未知キーと不正構造は従来どおり保護する。

## 入力と保存

- 上限は JavaScript `string.length` による500 UTF-16コード単位。BMPの日本語やLFは1単位、一般的な補助平面の絵文字は2単位。結合文字・複数コードポイントの絵文字は見た目1文字でも複数単位となる。
- `maxLength` で貼り付けを黙って切らず、超過入力をそのまま保持し説明と確認停止。普通の本文保存は可能だが備考は渡さない。
- 明示確認リクエストだけが備考を新規履歴に渡す。既存共有ロック、保存前照合、容量検査、読戻し成功前には成功表示しない。候補レコードは永続保存成功そのものではない。
- 保存待ちでは備考欄を無効化し、イベント側でも変更を拒否。失敗・競合・保護・再取得操作では入力をクリアしない。成功した明示確認だけでクリアする。
- 閉じる・ページ離脱では備考も未保存として警告。「編集に戻る」は入力を保持する。明示的に「未保存の編集を破棄して閉じる」を選べば破棄する。ページ再読込・タブ終了後の未保存入力復元は保証しないため、保護時は欄から備考も控える。
- 履歴20件、レポート全体UTF-8 JSON 1,000,000バイトは不変。備考も容量に含む。超過時は停止し、古い履歴を削除しない。
- 表示は React の文字列エスケープで通常テキストとして扱い、改行を保持し長文を折り返す。MarkdownやHTMLとして解釈しない。

## 互換性・ロールバック

新アプリは備考のない既存履歴を読める。空欄の `remarks: ""` を含め新フィールドを保存した後は、PR #68以前の厳格 validator は未知の確認項目として読込・通常保存を停止する。旧版でも書ける双方向互換ではないが、未知項目を削除して保存する経路は追加しない。旧版利用者との同一原本の併用は避ける。

ロールバック前は現在の原本JSONを必ず退避する。既存の保護表示「原本JSONをエクスポート」「元データをコピー」で原本を保持し、新版で読む経路を確保する。コードを revert しても保存データは自動変換されない。旧版のために remarks を削除したり保存領域を初期化したりしない。必要なら備考導入前に別途確保したバックアップを利用できるが、その後の履歴を失うため原本退避と人間の復元判断が必要。安全な第一選択は保存データを維持し対応版へ戻すこと。

## 検証範囲と限界

単体・保存回帰・既存6GUI条件を利用する。6条件の実体は Chromium desktop1365/390、Chromium touch375/390、WebKit touch375/390。WebKit desktopを新設する環境変更は行わない。500/501単位、絵文字、改行、危険文字、未記録/空欄、normal保存、非破壊、失敗/読戻し/競合、入力保持、履歴順、assessment独立性を検証する。

実機iPhone SafariのソフトキーボードやVoiceOverは未検証。WebKit自動試験やDOM関連付け検査とは区別する。実行結果はLOGおよびPRの最終HEAD CIを参照する。

# 同一メモの計算ブロック参照と手動再計算

2026-10-20 (JST)。基点 main `b1a590aa74808e82c7c3dfe3e02fa13984338450`（PR #36）。

## 既存構造と変更判断
- `CalculationMemoBlock` はID、式、表示式、内部result、resultText、errorを保持。欠落evaluationModeは従来電卓、`note-variables`はメモ内逐次Mapスコープ。`recalculateMemoBlocks` は追加情報を元blockから継承し計算管理フィールドを最後に更新する。
- 従来の `MemoBlockEditor` は追加・編集・削除・移動、`PlainNoteModal` は保存時に逐次再計算していた。既存メモの意味は維持する。参照を使い始めたメモだけ、永続 `calculationPolicy:{version:1,mode:"manual"}` に切り替える。最後の参照ブロックを削除しても手動方式を維持する。
- 旧検討の「前のブロックだけID参照」は採用しない。ID参照は前後の配置と無関係。**既存変数の上から順の束縛・再代入は別の契約であり、配置変更で意味が変わる**。新参照モードでは裸変数・代入を許可せず、その変数を計算した既存ブロックの結果を参照する。既存式を自動変換しない。
- 登録式は別の定義IDを持つライブラリ。登録式名とブロック参照を結び付けず、関数定義としてブロックを呼ばない。登録式入力への変数取り込みは手動メモの有効snapshotのみから読み、再計算待ちは拒否する。

## 保存と式の境界
新 `evaluationMode:"block-references"`、`references:{version:1,entries:[{slot:1,blockId:"..."}]}`。式の `@{1}` はローカルslot。GUI選択がIDマッピングを作り、内部ID入力は不要。登録式名・変数名と一致しても呼び出しにならない。未使用slotも削除せず保持し、式から外した参照が勝手に別対象へ変わらない。

字句上の参照tokenだけを内部symbolへ橋渡しし、残りは既存AST構文検証と数値評価で扱う。内部symbolの直接入力、代入、アクセス、任意関数、暗黙乗算を拒否。関数で計算した結果も丸め前のnumberをMapへ入れ、文字列化・表示丸め値の再利用はしない。計算エンジン本体、丸め規則、指数/深度/AST制限は変更しない。

`evaluationState:{version:1,status:"stale"|"current",signature?,attemptError?}` を各計算に保存。signatureはhashではなく、計算仕様・旧変数の先行束縛仕様・直接参照仕様/結果・自身の結果のJSON証拠。現在statusだけを信頼せず、表示と取り込み時に照合し、上流staleを依存先へ伝播する。これは改ざん耐性署名ではなく、JSON編集/状態不整合の保守的な検出。全ブロックの式や結果と証拠を協調して書換えた不正データの数学的正しさまでは認証しない。

既存version 1を維持し、optionalな形式境界を追加。旧版は未知modeを保護する。新参照形式/状態/方針の未知versionや不正型はPR #34/#36の全保存データ保護へ入り、原本保持・保存拒否・原本エクスポートを維持する。構造が正しい循環/参照切れ/構文エラーは編集修復可能な計算エラーで、データ破損と混同しない。

ブロック、policy、references、entries、evaluationStateの追加記述情報はspread継承し再計算でも消さない。計算管理フィールドだけ新結果で更新。未知フィールドを新しい計算意味として解釈しない。将来計算意味を変更する形式は新version/modeで必ず境界を立てる。proof/source metadataは保持しても、式変更後の証明の妥当性を自動保証しない。

## 評価トランザクション
`analyzeBlockDependencies` は共有構造解析からMapでID依存関係、エラー、互換性制約付きの非再帰実行順を返す。循環に依存するblockも停止。参照先が文章/数式/削除済みなら参照切れ。最大128計算ブロックと128slot/ブロックを手動計算の上限とし、深いchainの再帰スタックを使わない。

「メモ全体を再計算」で次を一つの同期transactionにする。
1. 参照構造と式/graphを検査。
2. 旧計算モードを従来の配置順scopeで各1回評価（旧assignment失敗時のscope維持も同じ）。旧モード内では失敗後も最後まで評価し、終了時に一件でも失敗があればID参照フェーズへ進まず全体失敗とする。
3. 新参照modeを依存元優先・ready ID昇順で各1回評価。既存sourceも今回の候補値だけを参照する。
4. 全計算が成功した時だけ、結果とsnapshotをまとめて置換する。

一件でも失敗すれば、成功した候補も含め旧結果を保持し、全体staleと失敗block番号/式を示す。旧モードで失敗した場合は最初の旧モードエラーを表示し、後続の間接参照エラーで覆わない。`evaluated`は旧モードでは`calculateMemoBlock`の呼出し（代入名の検査などで内部数値評価へ達しなかった失敗も含む）、参照モードでは`calculateVariableExpression`の呼出し（throwも含む）を順番に記録する。参照の構造検査や参照元確認で停止し数値評価へ達しなかったものは含まない。保存は式の修正とstale情報を保持できるが旧結果を新確定値にしない。編集/保存/プレビュー/並替え/登録式入力取り込みでは新modeを評価しない。

部分closure評価は将来候補。今回は旧変数スコープとID依存が混在するため、全体transactionを最小の検証可能な確定単位とした。**無関係の空計算やエラーも全体確定を止める**。空ブロックを埋める/不要なら利用者が削除して再計算する。計算関連の編集・移動は保守的に全計算をstale化。文章編集では結果を無効化しない。無関係な計算まで待ちになる性能/UX上の制約は意図的。

## UIと出力
ネイティブinput/selectのまま。IME/cursorを置換するリッチ入力は導入しない。参照slotと現在の表示位置を一覧し、削除先は明示。ラベル/色の既存識別設定は旧変数表示で維持し、参照の関係/状態は色に依存しない必須説明として表示。状態はeditor、保存カード/詳細、Markdown contentに反映し旧結果の誤認を防ぐ。手動方針・全体確定の説明はdetailsから参照できる。

## 将来と対象外
別メモ参照にはmemoId+blockId、読み取り権限、削除/世代管理、スナップショットの境界を追加する。今のslot対応は同一メモに限定。後続の[読み取り専用依存解析](dependency-analysis.md)でID/旧変数の構造化graphとMermaid文字列出力を追加した。表示順や名称をIDにしない。Excel的な一覧、Mermaid描画UI、Memo Nexus送信、ブロック関数呼出し、自動再計算は実装しない。既存エディタやアプリ間保存形式は統一しない。

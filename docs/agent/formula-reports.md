## 保存形式・制限

追加構造は `formulaReports: { version: 1, entries: FormulaReport[] }`。省略された旧データは空として扱い、読み込みだけでは新領域を生成しない。各レコードは `id`, `formulaId`, `title`, `body`, `createdAt`, `updatedAt`, `confirmedExpression: string | null`。ID/登録式IDの重複、未知領域version、不正日時/本文型/確認式型は拒否する。追加の未知付随フィールドは解釈せず保持する。

上限は全体200件（孤立レポートも含む）、ID120文字、タイトル1〜120文字、本文100,000 UTF-16コード単位、確認対象式2000文字、領域全体1,000,000 UTF-8 JSON bytes。文字数はJavaScript文字列長で、絵文字などは2単位になる。領域全体の容量は未知metadataも含む。件数や容量を超えても古いレポートを自動削除しない。履歴の圧縮・削除UIは今回実装しない。

`saveFormulaReport` は純粋関数で候補を作り、元レポート全体のJSON比較（暗号学的署名ではない）と現在の式文字列を照合する。通常保存はタイトル/本文変更で確認スナップショットをnullにし、明示確認保存だけが現在式を記録する。作成日時は保持、更新日時は保存要求内で設定し、保存成功は読戻しで別に確認する。レポートには安定ID、登録式ID、タイトル、本文、作成/更新日時、明示確認した式のスナップショットを保持する。式の名称変更は対応状態を変えず、式の文字列変更は要確認となる。文字列一致は数学的同値性や証明の正しさを保証しない。

## 保証境界と復旧

説明文、数値的な計算根拠、数学的証明は別物。計算成功・閲覧で確認状態を自動更新しない。本文を変更した場合は明示的な再確認が必要。証明・導出・適用条件・由緒・出典は空の編集テンプレートであり、史実や文献を生成しない。

共有ロック・原本比較・読戻しは現行アプリの競合抑止であり、旧アプリ・外部writerを含む完全な原子的CASや物理媒体への保存完了保証ではない。保存後読戻し失敗では書込み済みの可能性を表示し再試行を止める。容量超過や未知/不正レポートは切捨てず保存停止・非破壊保護にする。

旧アプリは新しい領域を知らず、保存時に落とす可能性がある。ロールバック前に原本JSON全体を退避し、旧版で新レポートを含むデータへ書き込まないこと。機能コードのrevertだけで説明文が旧版から安全に編集できるようになるわけではない。Markdownは本文救出用で、未知フィールド込み原本JSONの代替ではない。

## 対象外・未検証

Memo Nexus直接通信、MCP、双方向同期、PDF、AI証明生成/採点、自動証明検証、複数版管理は対象外。実機iPhone Safari、VoiceOver、native OS文字拡大は未検証。具体的な検証結果と対象HEADはLOG/PRを参照する。

## 操作例・レビュー対象

1. 登録式 `a+1` を登録して詳細から関連レポートを作成。`$a+1$` を含む本文を編集・プレビューし、通常保存では「未確認」を確認する。
2. 「現在の式に対する内容を確認して保存」で式との対応を記録する。式を `a+2` に編集すると「要確認」、名前だけの編集では確認済みのまま。
3. 本文を編集し途中で閉じると、保存せず破棄するか編集へ戻るかを選べる。失敗・競合時は本文をコピーで退避して再読込する。
4. 登録式を削除してもレポートは独立一覧に残る。同名の別登録式には自動付替えしない。孤立状態で再確認はできない。

実生成の空テンプレートは `FORMULA_REPORT_TEMPLATE`、合成テストデータと期待値は `tests/formula-reports.test.ts` / `tests/formula-report-ui.test.ts` / `tests/formula-report-app-save.test.ts` / `e2e/scenario.mjs` に残す。公開する画像・fixturesは合成データのみ。

第一希望は既存の安全描画・export処理の再利用で、採用済み。制約として既存Markdown rendererはCommonMarkの完全実装ではなく、リンク/コード/数式等の既存対応範囲を維持する。新エンジン追加は行わず、受け渡しには生Markdown本文を出力する次善策を採用する。表示と他Markdown環境の完全一致は保証しない。

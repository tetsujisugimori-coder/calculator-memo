## 操作と安全境界
点検画面に全件コピーと .md 出力を追加。出力対象は絞り込み前の全項目、見直し数は既存 needsReview の行単位 OR。未照合や不完全な集計でも、その状態・理由・認識数を明記して出す。0 件・一致・出力成功は利用者確認や数学的正しさを意味しない。

コピーとダウンロードは同じ同期 builder を呼び、本文・判定・取得時刻・識別情報を一括取得する。非同期 clipboard 完了時は context / acquisition / storage epoch / modal session を照合し、閉鎖・対象切替・再照合・失効後の完了通知や手動コピー用内容を現対象へ残さない。開始済み OS clipboard 書込そのものの取消は保証できず、出力内に開始時の対象と時点を固定する。コピー失敗は失敗表示と読取専用の全文手動コピー欄で復旧。出力文字列は React textarea の value として表示し HTML 実行しない。

既存 `reportCode` の動的 fence、`reportLines` の上限、`reportFilename`、`downloadMarkdownReport` を再利用する。文字列・識別情報は全文を安全なコードブロックへ置く。ファイル名のみ既存安全化/長さ制限を適用し、本文内のタイトル・IDは省略しない。400万文字を超えた場合は全出力停止と理由表示、部分成功扱いなし。

## 保証範囲・非対象
指定本文と取得した保存原本に基づく点検時点の独立記録。本文全文やsnapshot全文は含まず、元レポート/記録を復元するものではない。認識できない/破損領域の未列挙件数は不明で、既存 scanner の範囲を超える回復はしない。UTF-16 の開始/終了位置を明示する。

保存・再計算・確認履歴追加なし。schema/version/容量/計算エンジン/確認条件/挿入取消は不変。点検履歴の永続化なし。取得原本の常時最新性・任意外部 writer との原子的排他、ブラウザ download の OS 保存完了は保証しない。既存計算メモレポートとは別出力で、自動挿入・結合なし。rollback はコード revert のみ。

## PR #87 再レビュー P2：保持本文と保存本文の一致（2026-10-25、実装前設計）

- 原因：従来の `savedContextChanged` は report/formula props の差分だけを見ていた。実際の CalculatorApp は storage 通知後も旧 data と confirmedSerialized を保全して保存を停止するため、この経路を検出できなかった。従来の「外部変更・削除対応済み」は props 差替え経路だけの保証であり、実アプリ経路まで保証した記述を訂正する。
- 第一希望／採用：既存の保存保護状態を Library → Report → Audit に伝播する。Report の既存 storage 通知でも一時的な本文一致未確認を保持し、出典再取得では解除しない。Audit の既存同期失効処理でも直ちに同じ制約を捕捉し、React 描画前の出力・非同期コピー完了を保護する。
- 次善策：保存原本を再取得して対象本文の署名を比較する方式。追加取得と編集基準の再定義が必要になるため今回は不採用。出力時の暗黙取得は行わない。
- 保証範囲：保存領域の更新は対象レポートの変更・削除を意味しないため「画面に保持した本文」「現在の保存本文との一致は未確認」とだけ表示する。編集基準との未保存差分と、出典照合の取得世代は独立。出典の再照合や点検の閉鎖・再表示では本文一致を格上げしない。編集内容・保存原本・確認履歴には書き込まない。

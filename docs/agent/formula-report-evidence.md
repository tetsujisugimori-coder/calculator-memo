# 登録計算式レポートの確認根拠（Issue #61）

## 目的と境界

登録式の説明資料から、利用者が確認した式定義と保存済み計算記録を追跡する。数学的証明・同値性・出典の信頼性を自動検証しない。根拠記録の再計算、現在のメモや未保存編集・試算からの補完は行わない。

## 実装前調査・設計判断

PR #60 を含む main `4b87b370e348740c090c0ed7ec4a9a1c6f8067d8` を基点とする。登録式は安定ID/名称/式を持ち、変数の独立定義や既定値は持たない。参照変数は既存 `inspectFormulaDefinition` で構文解析される。実行画面の入力値は `formulaExecutions` で別管理され、式定義ではない。計算済み履歴は各保存メモの `calculationEvidence` に安定記録IDで保存されている。

第一希望は既存の保存成功境界・構文解析・保存記録詳細表示を再利用し、レポートだけに確認情報を追加すること。独立した計算器・入力履歴・意味解析を追加しない。式文字列と抽出変数（順序を含む）をversion付きで保存する。数式が等価でも表記が異なれば変更扱いであり、未知の意味情報を一致と断定しない。

旧 `confirmedExpression` には変数/確認日時/確認対象本文がない。旧値を残したまま新基準では比較不能と説明し、現在時刻で補完したり、開いただけで新形式の確認履歴を作らない。利用者の再確認保存で新しい履歴を追加する。

## 保存構造

トップレベル `version:1` と `formulaReports.version:1` は維持する。各レポートの optional `evidence` にversion、選択した記録への `links`、追記確認履歴 `confirmations` を保持する。

- リンクは `{memoId,recordId}`。同名メモ・異なるメモの同じ記録IDを混同しない。メモ間で計算参照を作るものではない。
- 確認は安定確認ID、登録式ID、確認日時、式定義（version/式/抽出変数）、確認対象タイトル/本文、選択根拠リンク、選択した記録の完全JSON照合情報を保持する。短いハッシュや暗号署名ではなく、同一IDの外部差替も検出するための内容比較である。記録の表示名は比較に含めない。照合情報も総容量に含む。
- `confirmedExpression` は互換保持用に最初の非null値を残す。最新の確認状態は `evidence.confirmations` を使い、旧値を最新状態と誤表示しない。
- 新しい確認を追加しても以前の確認を上書きしない。本文/タイトル/リンクの変更は現在内容を未確認にするが、過去の確認対象と式は残す。
- リンク最大20件、確認履歴最大20件。既存のレポート領域全体1,000,000 UTF-8 JSON bytesを変更しない。本文複製も容量へ含め、超過時は保存停止。無断切捨て・履歴自動削除はしない。

第一希望は過去の確認対象を正確に再読できること。短いハッシュだけにする次善策は本文復元ができず、今回は採用しない。大きい本文は20回未満でも総容量へ達し得る。将来の履歴管理・圧縮は別設計とし、今回の読込や通常保存で履歴を整理しない。

## 操作・状態

登録式ライブラリの「関連レポートを閲覧・編集」から、根拠詳細を展開する。保存済み記録を選び、追加したリンクはレポートの明示保存で確定する。選択や詳細閲覧だけでは保存されない。確認操作はその時点の本文・式・選択根拠に対する利用者の確認である。

- 確認済み・式一致: 対象本文/選択根拠と式定義を照合できる。
- 確認済み・式変更あり: 現在の式または抽出変数が確認時と異なる。
- 未確認: 新規、または現在の本文/タイトル/根拠選択が最後の確認対象と異なる。
- 根拠不足または判定不能: 旧形式の情報不足、式欠落、未対応情報、根拠欠落/破損など。理由を併記し、一致や参照成功としない。

本文/タイトル/選択根拠を最新確認対象と完全に同じ内容へ戻した場合は、同じ確認対象として照合できる。途中の未確認編集すべての版管理は行わない。確認日時は明示確認要求で生成した時刻であり、書込み後読戻し完了時刻ではない。

確認履歴の本文は当時の説明であり、現在のMarkdown編集を置き換えない。確認日時と記録の計算日時・保存要求時刻は別物である。

## 保存・競合・非破壊性

保存記録は原本読込を開いた時点で固定する。明示再取得以外では現在の編集へ追従しない。外部更新を検出したら警告し、失敗した再取得で前世代の値を新しい結果として残さない。ID欠落時は別の記録に置き換えない。同じIDの内容差替では当時の根拠として詳細を表示せず、利用者が現在取得した記録として明示表示する場合も未確認であることを説明する。

保存時は既存共有ロック内で元レポート、式定義、選択した原本記録、保存原本を照合する。候補作成と書込み成功/読戻し成功は区別し、成功確認前に確認済みを表示しない。不確定書込み後の盲目的再試行は停止する。既存の未知フィールド保持と未知version/不正構造の非破壊読込保護を維持する。

## 互換性と復旧

根拠領域のない旧保存データは読める。読込のみでは追加領域を書き込まない。未知・不正な根拠構造は元JSONを保護し、自動修復・削除しない。旧版へ戻す前は同じオリジンの `calculation-memo:data` 原本JSONを退避する。Markdown出力だけでは確認履歴と数値根拠のバックアップにならない。旧版は新しい根拠状態を正しく理解できないため、新形式データを旧版で編集・確認・上書きしない。コードrollbackと保存原本復旧を分離する。

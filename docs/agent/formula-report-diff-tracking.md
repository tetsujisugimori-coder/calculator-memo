# 比較差分の出典追跡

## 第一希望と保存境界

既存の引用・根拠 UI を拡張し、PR #81 の明示挿入にだけ追跡情報を付与する。両記録の固定 snapshot、元引用の登録式/メモ/ブロック/引用 ID と日時を通常 Markdown のバージョン付きフェンスに保持する。開始マーカーと終端メタデータの差分 ID が対応し、既存 validator で構造を検査する。可視本文だけの文字列一致から出典を推定しない。元引用 snapshot はコピーして保存し、自動更新・再計算・確認履歴追加は行わない。

別のトップレベルメタデータ保存は、旧 reader の未知フィールド保護と移行が必要になるため次善策とし不採用。本文内の方式はコピー/Markdown出力でも情報を維持できる反面、情報の削除・手編集・外部加工に弱く、真正性の署名ではない。未知/不正な追跡情報は修復・削除しない。現在の保存スキーマ/version/上限/確認状態条件に変更はない。

## 引用時点と現在

比較元は元の固定引用 snapshot、比較先はその時点に明示選択された同一メモの別保存記録。差分 ID は新規差分自身の識別子、プレビュー準備日時は実際の準備時刻であり保存完了や確認日時ではない。計算日時/保存要求時刻/元引用日時は存在する値だけを表示する。確定計算記録の現行形式には独立した利用者確認日時はないため「記録なし」とし、レポート確認履歴から推測しない。

現在の照合は同じ取得原本に含まれるメモ ID + 記録 ID の両記録全体と固定 snapshot を比較する。同一 ID だけでは一致と扱わない。本文編集は現在の出典状態とは別に表示する。取得成功しても未知/不正構造なら照合不能、見つからない場合は欠落、取得に失敗した場合は取得失敗とし欠落を推定しない。他タブ更新時は未照合へ戻す。

引用時点の比較は保存された両 snapshot を既存比較処理/表示部品で再表示する。現在の出典同士の比較は独立した明示操作であり、過去の引用を置き換えない。対象や本文・取得原本が変われば以前の詳細/比較表示を破棄する。関連付け解除も出典欠落とは別に知らせ、自動リンク追加はしない。

## 旧差分と限界

PR #81 以前の通常 Markdown 差分には両記録の snapshot と一意な追跡 ID がないため、認識可能な見出しには「追跡情報不足」と表示する。現在の記録や見た目の ID から復元・後付けしない。見出しも追跡マーカーもすべて削除された任意の文章は自動検出できない。

同一メモ内のブロック ID だけで対応付ける。現在のメモ本文や未保存 draft、未確定試算は対象外。現在記録の変更理由、説明の正誤、数学的証明の成立、記録の真正性は保証しない。観測時点以降の任意外部 writer を原子的に固定する機構ではない。

## 容量・操作・拡張

両記録の保持により本文量が増える。100,000 文字/レポート全体 1,000,000 バイトの既存 preflight と保存検査を維持し、超過は全文拒否、履歴切捨てや容量緩和をしない。開始/終端の間へ引用や差分を挿入しない。取消は PR #81 の直後全文一致条件を維持する。

モバイルは既存縦配置、折返し、Modal フォーカス管理を使う。状態は色ではなく文言で区別する。既存確認履歴の見直しや将来証明機能への拡張は、引用時点/観測時点/利用者確認を別概念として維持する必要がある。

ロールバックはコードの revert のみ。本文は通常 Markdown として保持でき、データ移行や元記録復元は不要。実行済み検証は LOG と PR の最終 HEAD CI を参照。実機 iPhone Safari/VoiceOver/OS キーボードは自動 Chromium/WebKit と区別する。

## PR #83 P2: 厳密な領域境界（2026-10-25 JST）

挿入ガードと出典読取は同じ `scanDifferenceEnvelopes` を利用する。既存 Markdown パーサーで実際に独立した code block と認識されたマーカーだけを対象とし、通常のコード・数式内の文字列を境界と見なさない。開始は `calculator-memo-difference-start-v1`、終了は `calculator-memo-difference-v1` の完全一致、双方の実フェンス閉鎖、開始の既知の厳密 JSON 構造、終了の既存 snapshot validator、同一差分 ID がすべて成立した場合だけ有限領域を閉じる。既存 validator は循環依存を作らない中立モジュールへ移しただけで、保存契約を変更しない。

従来は予約接頭辞に一致する任意の中間フェンスで保護を解除していた。未知の preview フェンス、将来版、破損、開始の重複・入れ子、ID不一致などが対応を曖昧にした場合は最初の開始位置から本文末尾まで保護し、後のもっともらしい終端で再開しない。出典UIもその範囲を不正／対応不明とし、snapshotや現在出典の一致表示を露出しない。既知開始の終端欠落は追跡情報不足。本文・メタデータの自動修復や削除は行わない。

第一希望は安全な範囲のみ挿入可能にすること。壊れた領域の後の文章まで挿入を拒むのは意図した保守的な妥協であり、任意の将来形式の閉じ方を推測する次善策は不採用。完全に対応する通常v1の直前・直後、複数の正常差分間は引き続き挿入できる。開始そのものが削除され、単独の既知・検証済み終端だけが残った場合の従来の「本文対応は保証できない編集済み記録」表示は維持する。削除されたマーカーの元の範囲や予約接頭辞まで失われた任意文章の出典は推測できない。

位置はパーサーの元文字列 UTF-16 範囲を使い、textarea の改行正規化位置を既存変換で対応付ける。LF/CRLF変換だけでは原本文を書き換えない。選択範囲は削除せず、その開始位置の前へ追加する既存契約のため、選択の末尾が保護領域をまたいでも開始が安全な外側なら許可する。拒否時は返却本文・caret更新・保存を行わず、直後全文一致による専用取消も変更しない。

検証結果・対象 HEAD・実 CI は LOG と PR コメントを参照。安全性はこの認識可能なマーカーと既存 Markdown パーサーの範囲に限り、全破損文書の元構造復元、真正性や数学的正しさの証明ではない。

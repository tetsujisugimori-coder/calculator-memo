# A/B比較結果の本文固定挿入

## PR #95 P2追加: 正規終端が一意でない資料
同じ資料IDの正規終端が早期に複製され後方にも残る場合、最初の終端を確定境界として採用すると内部点検記録がA/B候補へ漏れる。厳密なMarkdown blockと既知JSONから、同じIDの次の厳密valid startまでの正規終端一意性を事前に確認する。複数なら元開始からEOFを不完全領域として保護し、後方のもっともらしい終端で回復しない。異なるIDの開始・未知/不正開始ではこの検査をリセットしない。

ID重複は出力rangeのmetadataからではなく、厳密valid start全件から数える。poisonや交差でmetadataが消えても既知の重複を忘れず、他の資料をcompleteへ格上げしない。未知・不正startは推測計数しない。

正常にそれぞれ閉じた同ID資料二つは従来の重複ID判定を維持し、間の独立根拠や旧v1/v2記録まで無根拠に消さない。普通のコードフェンス中のマーカー風文字列は不活性。形式・保存schema・比較結果・Markdown bytes/日時・明示挿入/失効/取消・容量保護は不変更。[再現と独立検証](../maintenance/pr95-boundary-20261026/README.md)。

第一希望を採用する。同一の既存比較result/metadata/取得世代から既存純粋Markdown builderで作った出力を、そのまま固定資料領域で包む。既に全文出力プレビューがあれば同じbytesを使い出力日時を作り直さない。挿入のための再比較・保存原本の暗黙取得・再計算は行わない。追加確認は既存点検モーダル内に置き、新たなモーダル階層を増やさない。

既存点検記録形式の流用という次善策は、比較資料を次のA/B候補にしてしまい単一点検の意味・自己参照境界を壊すため不採用。独立保存領域・snapshot再複製も容量と互換性負担を増やすため不採用。本文内に専用の最小v1識別境界（資料ID、登録式/レポートID、A/B記録ID、挿入プレビュー準備日時）を追加する。比較資料の生成日時は既存Markdown内の出力日時であり、準備日時や実挿入時刻と混同しない。準備済み全文の実行時再生成はしない。

厳密なMarkdown block scannerを再利用し、資料内の引用/差分/点検記録風文字列を先に除外し、重複ID検出へ混入させない。外側の正規根拠は保持する。未知version・破損・入れ子・交差・偽終端・重複・未閉鎖は保守的に保護し、推測修復しない。固定資料は挿入前の本文内A/Bの比較であり、挿入後本文の新点検結果ではない。

既存カーソル挿入・容量検証を再利用する。範囲選択は先頭へ追加し文章を消さない。編集位置の実変化とモーダルfocus移動を分離し、本文/対象/関連付け/比較result/取得/保存通知/編集位置が変わればプレビュー失効。実行直前にも同じ情報を照合する。専用取消は対象・編集世代・通知世代・本文・正確な範囲の一致で直前挿入だけに限定する。別編集・保存・別挿入・通知後は拒否し文字列検索で削除しない。

schema/version/容量上限/計算/確認条件は変更しない。仮容量検証は保持collectionを使い現在の保存原本との原子的整合を保証しない。保存は既存の明示操作のみ、失敗時や制約発生時も過去記録・snapshot・確認履歴は保持する。

## 取消の利用可否・フォーカス（R2）
初版は実行時拒否だけを行い、既知失効後も有効な取消操作を残していた。「利用可能な場合だけ提示」に合わせ、同じ本文・対象/取得世代で未失効のときのみ表示する。編集や通知で永久失効し、本文を同じ文字列に戻しても復活しない。失効理由は非操作テキストで表示し、消える取消操作にfocusがあれば理由へ移す。遅延イベント/同一turn競合は実行直前の同期epoch・範囲guardで拒否する。安全な取消成功時のfocusも本文に戻す。保存・確認の意味は不変更。

## Unicode位置の非破壊拒否（R3）
既存の文字位置挿入はUTF-16単位であり、APIによるsurrogate対中間選択を許すと正常な絵文字を分断できた。新しい比較資料prepareだけに純粋な本文/位置検証を追加する。元本文がwell-formed UTF-16であること、textareaの改行正規化後の整数範囲・順序・start/endのsurrogate境界を検査し、不正は全体拒否する。本文の修復・置換・切り捨てはしない。既存の他挿入へ無断で仕様を拡張しない。通常のブラウザ操作で中間位置が選ばれることは未確認であり、programmatic selectionの負例として明記する。独立同期待値9成功/3失敗→12/12成功。正常なLF/CRLF/Unicodeの挿入と専用取消は統合試験で別に確認する。

# 固定引用と別の保存記録の比較

## 採用案と境界

固定引用の状態から「別の保存記録と比較」を開く。比較元はMarkdownの追跡情報に保持された、既存validatorで検証可能な引用時の記録全体である。現在取得した元記録へ置換しない。元記録が変更・削除されても引用snapshotを比較元として使える。本文を手で編集した場合は、その文章でなく追跡情報の記録を比較すると説明する。未知形式、不正形式、異なる登録式ID、重複引用IDは推測比較しない。

比較先は同じ登録式のレポートに**保存済み**の根拠リンクにある別記録から利用者が明示選択する。未保存のリンク編集を混ぜず、日時順で選ばない。同じメモIDだけを候補にする。別メモでは同じ見た目のブロックID・式・名前に同一性の保証がないため、ブロックを推測対応させない。対象リンクの記録が欠落した場合と未知・不正な場合は別に表示し、根拠の取得失敗を欠落とは断定しない。適格な別リンクがない場合は理由を表示し、リンクや記録を作成しない。

## 再利用と第一希望・次善策

- 採用した第一希望: 既存 `compareEvidenceRecords` に引用snapshotと明示選択の記録を渡す。RecordInfo/BlockInfo、evidenceRowLabel、レスポンシブなevidence-pair、Modalのフォーカス復帰を共用する。式・計算モード・実使用参照元ID/旧変数名/内部値・表示/内部結果・本文/実行順、安定ブロックIDによる追加/削除を既存契約どおり表示する。丸めた表示が同じでも内部値や負のゼロは区別する。
- 次善策: 既存保存記録画面へ単に移動する方法は、消えた引用元を基準にできず、当時のsnapshotが現在原本へ置換される危険があるため採用しない。
- 保存形式の拡張や別比較台帳は不要。独自の影響分析や経路探索は追加しない。引用ブロックを初期の詳細対象とし、同じ記録内の他ブロックへ明示選択で進める。

差分は取得した記録間の観測結果に限る。因果関係、編集意図、説明の誤り、数学的正しさの自動判定ではない。日時は保存された文字列を表示し、保存要求時刻を完了時刻に読み替えず、欠落を現在時刻で補わない。

## 同じ取得時点・保存保護

親の既存保存原本取得経路を共用する。比較モーダルはstorageを独立に読み直さない。比較先変更では詳細ブロックを引用ブロックへ戻す。本文・引用・原本notes・保存済みlinks・取得時刻が変わったら古い選択を無効化する。未照合/取得失敗中は差分を表示せず、明示再取得後も比較先を選び直す。再取得ボタンは親の既存処理を呼び、編集中本文は保持する。

選択、比較、閲覧、閉じる、再取得は保存writer、数値評価器、確認処理を呼ばない。引用本文・元記録・リンク・履歴を更新しない。既存の引用状態（元記録の変更/欠落、本文編集、リンク解除）は別表示のまま保つ。過去の確認備考や現在のformulaReportAssessmentの条件も変更しない。

同一タブ/別タブの既存更新通知範囲に従う。任意の外部writerとの原子的排他や、通知されない変更の即時検知を保証しない。「取得時点」と表示し、最新値の保証と混同しない。

## UI・互換性・戻し方

比較元/先を「引用時」「比較先」と文章で区別。完全なメモID/記録ID/日時/選択ブロックIDを詳細へ表示する。native selectの選択肢は番号と短いIDとし、長いIDでWebKitが横幅を膨張させない。小画面では縦配置、長い式/内部値は折り返す。既存ModalのEscape・キーボードフォーカス復帰を使う。

保存schema/version、100,000文字/全レポート1MB/履歴20件、計算エンジンは変更しない。旧データの移行なし。コピー/Markdown出力は従来どおり引用本文をそのまま保持し、比較表示は挿入しない。ロールバックは本機能のコード・テスト・文書をrevertすればよく、保存データの書換えやフィールド削除は不要。原本JSON退避の既存機能を維持する。

## 検証

単体では元記録変更/欠落、内部値、実使用入力、追加/削除、異メモ、未知/不正引用、取得失敗、選択切替・再取得・stale、本文と原本/履歴不変を検証する。既存6条件のGUIへ主要操作を追加し、両テーマ200%と375/390px、キーボード、フォーカス復帰を確認する。30分上限、PNG114枚程度、成功trace非保存は維持。実行結果はLOGと最終HEADのPR Checks参照。実機iPhone Safari・VoiceOver・iOSソフトキーボードはWebKit自動試験とは別の未検証事項。

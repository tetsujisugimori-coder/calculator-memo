# 登録式ライブラリの根拠状態一覧（Issue #65）

## 第一希望と実装
既存ライブラリへ小規模に統合し、`formulaReportAssessment` を唯一の意味判定として再利用する。`useFormulaSavedSnapshot` は PR #64 の loadData・取得日時・storage 更新検知・明示再取得を抽出した読み取り専用の共有元。一覧と詳細は同じ検証済み原本・stale 状態を使い、片方だけが古い確認済みを表示しない。保存形式や新しい永続状態は追加しない。

一覧の表示分類は confirmed=確認済み、changed=要再確認、unconfirmed=未確認、unknown/orphan=状態判定不能。レポートがない場合は根拠なし（レポート未登録）、外部更新検知後または保存原本に対象IDがない場合は根拠未照合。これはUI分類であり数学的判定ではない。未取得・取得失敗・内容不一致を同じ成功状態へまとめず、詳細に既存の理由を表示する。

## 保存・編集・復旧
- 状態は保存済み式・レポート・notesのみ。編集propsの式名や内容は既存編集操作用として残すが、状態計算に渡さない。未保存通知を維持する。
- 同一タブの保存完了（pendingSave true→false）では読み直す。レポート閉鎖時も取得する。ただし外部更新を検知済みなら自動再取得せず、利用者の明示再取得を待つ。
- 外部更新で一覧全体と詳細を未照合へ下げる。再取得失敗は判定不能で、以前の確認済みへ戻さない。アプリ全体の競合保護は解除しない。
- loadData の既存検証と原本保護を通す。未知/不正情報を補完・削除・自動修復しない。通常保存の禁止条件は変えない。原本JSON保全・復旧は既存設定画面から行う。
- 絞り込みはローカルUI状態のみ。登録順序・selectedId・レポート履歴を保存しない。同名でもIDで詳細へ移動。フィルター対象外になった選択は説明付きで保持する。
- 既存の編集・キャンセル・削除/取消・孤立レポート救出・実行を維持。詳細は既存画面を使用し重複画面なし。

## 制約・次善策
第一希望を採用でき、新エンジンや状態判定の二重化は不要。独自の検索欄は元のライブラリに存在しないため今回追加しない。再取得は確認操作ではなく、古い履歴を新たに承認しない。実機iPhone Safari/VoiceOverは自動WebKit検証とは別で未検証。

## 追加レビュー R3：UTF-16文字境界（2026-10-26 21:01 JST）
全受入条件の再照合でUnicodeと不正位置の扱いを再確認し、P2を検出した。既存の共通挿入関数はUTF-16位置で本文を分割するため、`😀tail` の位置1（surrogate対の途中）を受け付ける。新比較資料の準備もこれを無条件に再利用し、有効文字を分断できる位置や既存の孤立surrogateを拒否していなかった。通常のキー/タッチ入力がこの位置を生成するかは未検証であり、jsdomの実textarea `setSelectionRange` が位置1を保持する経路で独立再現した。

独立試験に3つの非破壊拒否条件（挿入先頭がsurrogate対の途中、選択終端が途中、元本文に孤立surrogate）を追加した。選択終端は文字列置換に使わないが、不適正な選択範囲を有効な位置として提示しないため両端を検証する。

実装担当は純粋な `assertAuditComparisonInsertionPosition` を新比較資料のprepareに限定して追加した。元本文の整形式、textarea改行正規化後の整数・範囲・順序、両端のsurrogate境界を検証し、推測修復や切捨ては行わない。既存の他挿入機能の意味や保存schemaは変更しない。差分読解でこの限定を確認した。

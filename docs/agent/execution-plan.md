# ID参照を主軸とする実行計画

2026-10-20 (JST)。基点はPR #38マージ後のmain `7fd8934ff3a04a3f43cd50ef5cbe77286ff55014`。保存形式、計算エンジン、内部精度、全成功時のみの一括確定を変更しない。

## 標準導線と既存データ

「＋ 計算」は既存の `block-references` mode / `references.version:1` を使う未評価ブロックを作る。数値だけの式にも使え、参照先は表示番号・式の一覧から選ぶ。内部IDを入力させず、式の `@{slot}` と安定したIDの対応を既存形式に保存する。追加・編集・保存で数値評価しない。メモは従来のmanual policyへ移る。

「＋ 旧変数計算」で従来の `note-variables` ブロックを明示追加できる。旧メモだけの場合は従来の自動逐次計算、manualメモでは手動全体再計算となる。既存ブロックを自動変換しない。従来電卓の `%` / x乗算、旧変数の文法・代入、登録式ライブラリ、履歴、単独メモは変更しない。

## 共通解析と実行順序

PR #38の `analyzeMemoDependencies` の構造解析を `dependency-structure.ts` へ分離し、Mermaid/変更影響と `createMemoExecutionPlan` が同じ `analyzeMemoDependencyStructure` を使用する。字句・AST検査と上限は `reference-syntax.ts` の既存実装であり、新しい文法や文字列検索は追加しない。公開の既存APIは再exportまたはwrapperで維持する。

計画は次を別々に返す。

- `graph`: 共有データ依存グラフ。ID確定辺、旧変数の不確定候補辺、解析診断。数値評価しない。
- `dependencies`: 確定ID辺だけの実行用参照。旧変数候補を実行依存と誤認しない。
- `constraints`: `legacy-sequence`（旧計算の配置順）と `legacy-phase`（旧フェーズ完了後にID計算）。データ参照ではない。
- `legacyOrder`, `referenceOrder`, `order`: 計画順。実際の試行は従来どおり `evaluated` で別に返す。
- `errors` / `diagnostics`: preflightを止める構造エラー。旧変数の構文/未定義、保存済みエラー、静的な束縛候補は先行して数値失敗扱いにしない。

従来どおり構造preflightのあと、旧モード全件を表示順に実行する。再代入が失敗しても古いscopeを保ち、後続の旧計算まで続け、最初の旧エラーを全体停止理由にする。一件でも失敗したらIDフェーズを一切実行しない。

旧フェーズが成功した後、IDブロックを依存元から評価する。毎回、評価可能になったIDのうちUTF-16文字列比較で最小のIDを選ぶ（localeには依存しない）。初期queueだけをsortする方式ではない。前後どちらの表示配置でもID結果/IDフェーズの順序は一致する。旧変数間の表示変更は従来どおり意味を変えるため、その非依存性までは約束しない。

## エラーの優先順位と設計変更

維持するもの: 構造エラーを数値評価より先に検出すること、参照構文/参照切れを表示順で選びその後に循環診断を扱うこと、旧変数フェーズの最初の失敗、失敗再代入後のscope、IDフェーズに入らない停止条件。

変更するもの: 独立したIDブロックが複数とも数値失敗する場合、先頭は従来の表示順に由来するqueue順ではなく、canonical ID計画で最初に試行して失敗したブロックになる。これは表示順非依存・決定的実行という今回の要求による意図的差分。成功値や旧変数の数値意味論の変更ではない。失敗したIDの後を無理に計算して別エラーを収集せず、未試行を成功と称さない。旧数値結果を代替に使わない。

自己参照、真の循環成分、循環下流はPR #38と同じ診断で区別する。参照切れ、参照形式不正、参照式解析失敗も分ける。旧変数はID構文を読めず、IDモードは裸変数/代入を許さないため、現行文法でID→旧変数→IDという逐次制約との逆向き循環は成立しない。不正な混在式は既存文法エラーにし、推測で変換したり新しい混合スコープを設けたりしない。将来の文法拡張時は制約グラフも含めた衝突設計が別途必要。

## 失敗の局所性と一括ロールバック

再計算の返値 `diagnostics` は今回の解析/試行による原因ブロックと確定ID下流だけを示す。旧変数の不確定候補辺は失敗伝播に使わない。失敗した再代入の後、以前の値で成功した消費側に誤ってエラーを付けない。無関係のブロックへ個別エラーを伝播しない。

ただし全成功時だけ確定する契約はそのままで、失敗時は全ブロックの旧値・旧error・未知metadataを保持し、全体staleにする。既存 `attemptError` は互換性のためメモ全体の一括確定停止通知として保持する。これは各ブロック自身が失敗したという診断ではない。今回の局所診断は派生情報で保存しない。エディタ内で今回の診断を表示し、編集時に消す。再読込後に古い実行診断を現在の診断と偽らない。現行の唯一の呼出し元はモーダルを閉じるとunmountし、別メモは新しいeditorを作る。同一mount中の外部同期/メモ切替は未実装であり、将来追加する場合は診断と対象snapshotの照合が必要。

## Mermaidとの対応

Mermaidは引き続きデータ関係を描く。確定ID辺はすべて実行計画に従い、sourceはtargetより前に評価する。一方、点線の旧変数候補は実行成功が未確定の静的候補であり、値束縛の確定結果ではない。旧順序制約とフェーズ境界はMermaidに新しいデータ辺として足さず `constraints` に分離する。このため図で無関係に見えるIDブロックでも互換性上は旧フェーズの完了を待つ。

図の保存済みエラー/再計算待ちはsnapshotの情報であり、修正後の再計算を妨げない。共有構造解析はpendingを判定せず、従来の `analyzeMemoDependencies` wrapperだけがsignatureによるpendingを付加する。

# 登録式詳細の閲覧（Issue #63）

## 第一希望と実装範囲
既存ライブラリ内へ小規模な閲覧専用 `FormulaDetailView` を統合する。別ルート・新保存形式・新評価器は追加しない。選択した安定IDに対応する保存済み式、構文抽出変数、Markdownレポート、根拠確認状態、確認履歴を表示する。変数説明の保存欄は現行形式にないため、その不在を説明し推測しない。

ライブラリの選択はローカルUI状態とし、選択だけで従来の `selectedId` 保存を呼ばない。編集・登録・削除・取消の既存保存経路は維持する。次回の起動時選択は保存済み selectedId に戻る。閲覧の無変更を優先した判断であり、新しい選択永続化は行わない。

## 原本・確認の境界
- `loadData` で取得した保存済み原本だけを使用。ライブの編集props・試算結果を詳細の根拠へ渡さない。
- 未保存編集がある場合は警告し、詳細は取得済み原本であると明示する。編集の保存成功または関連レポート閉鎖後は原本を読み直す。
- 他タブのstorageイベント後は取得時点の表示を保持し、現在状態を「根拠未照合」とする。明示的な再取得でのみ最新原本へ進む。
- 保存不能・未知形式・未知フィールド・容量超過は既存 `loadData` 保護に従い判定不能。原本を書き換えず、設定の原本JSON保全・復旧導線を案内する。
- `formulaReportAssessment` が唯一の判定源。confirmed=確認済み・式一致、changed=要再確認・式変更あり、unconfirmed=未確認、unknown=根拠不足または判定不能。原本更新検知の「根拠未照合」はUI一時表示で、新保存状態ではない。
- 履歴ごとの照合も同じ判定関数へ当該履歴を渡す。履歴自体を現在の確認へ昇格させない。日時・確認ID・定義形式・式・変数・本文・関連計算記録は実データだけを表示する。
- 説明・数値根拠・数学的証明は別物。文字列・抽出変数の一致は数学的同値性や正しさの証明ではない。

## 表示・操作
縦方向の既存モーダル内で閲覧する。本文は `MarkdownContent` / KaTeX、履歴根拠は `HistoricalReportEvidence` を再利用する。履歴と長い原文はdetailsで折り畳む。コピーとMarkdown出力は保存済み本文の完全な文字列で、既存download関数を利用し保存・再計算を行わない。

「関連レポートを閲覧・編集」「登録式を編集」は既存の明示編集へ進む。編集画面の未保存破棄確認、競合検知、保存後読戻し、履歴20件・容量制限を変更しない。登録式削除後の孤立レポート救出も維持する。

## 検証・制約・復旧
単体で無保存・無計算、原本限定、同名ID分離、全確認分類、旧履歴、欠落/差替え根拠、未知/破損/読取不能/容量超過、20履歴、他タブ更新、コピー・出力を確認する。GUIは既存6条件・両テーマ・文字拡大の中へ詳細の表示、キーボード開閉、完全な原本不変、コピー/出力を追加する。画像114上限と30分、成功trace0/失敗時trace維持。実機iPhone Safari/VoiceOverは別途未検証。

保存形式とデータ移行は変更なし。ロールバックは本PRのUI/テスト/文書コミットをrevertする。レポート・確認履歴・未知原本を削除する必要はなく、旧版の非破壊保護に従う。

## PR #64 追加検証：更新経路と保護

- 同一タブではstorageイベントに依存しない。式編集中は詳細を表示せず、編集終了とpendingSaveの遷移で再マウントし原本を読み直す。レポート編集は閉鎖時のdetailRevision更新で再取得する。保存済みの式・本文・既存assessmentを照合する。
- 他タブの実UI保存ではブラウザのstorageイベントを受け、取得時点の旧原本を明示し現在状態を根拠未照合へ下げる。明示再取得後もアプリ全体の競合保護を解除せず、参照だけで再保存しない。
- 式キャンセルとレポート破棄では保存原本の文字列全体・確認履歴を同一のまま維持する。再取得は新しい確認の生成ではない。
- `confirmation.definition` の表示は `loadData` → `readFormulaReports` → `readReportEvidence` を通った値だけに限定。null、配列、不正version、variables、links、confirmations、旧履歴の未知項目を含む保護ケースをUI入口で検証する。未対応原本を部分的に正常化して表示しない。
- 登録式の未知フィールドは既存の対応version読込で失わず保持し、assessmentは確認済みにしない。通常保存のround tripでも原本フィールドを維持する。未対応レポート根拠形式とは保護方法を混同しない。
- 未取得（根拠未照合）、読取失敗（判定不能）、式変更（要再確認）、本文編集（未確認）、記録差替え（判定不能＋不一致理由）を既存の状態と理由表示で区別する。過去の確認は現在の内容への承認ではない。

再現テストで製品不具合が確認されない場合、製品コードは変更せず検証と記録だけを追加する。最終実測結果はPRの追加検証コメントを参照する。

# 計算確定時の根拠スナップショット

2026-10-22 JST。調査基点: main bf09f8d（PR #50 merge）。

## 実装前調査と設計判断

既存 execution-plan は旧変数を本文順で全て評価した後、ID参照を依存順に評価する。旧変数の再代入失敗は直前の成功値を維持し、手動メモは一件でも失敗すると全体の結果を rollback する。試算は同じ純評価器を呼ぶが永続保存しない。鮮度 signature は構造の比較情報であり、過去に実使用した値の履歴ではない。PR #50 の Markdown は現在の保存値と使用値確認不能を既に区別する。これらを再実装せず拡張する。

「根拠記録の確定」は全件の計算成功に加えて明示的な「保存する」の書込み・読戻しが成功した境界とする。再計算／試算反映の直後は未保存候補である。プレビュー、通常編集、失敗、取消では確定記録を作らない。同じ内容を繰り返し再計算した候補は別々に記録する。後続の編集・失敗で失効した未保存候補は保存対象にせず、保存済み履歴は変えない。旧自動モードは既存の保存時評価と同一パスで取得し、部分成功の保存挙動は維持するが根拠は全成功時だけ記録する。

note 単位の任意 calculationEvidence.version=1 に一括記録を追記する。計算日時、保存要求時刻、一意 ID、評価器方式 calculator-memo-v1、各ブロックの本文位置・実行順・入力式・モード・参照枠・実使用入力・結果を保持する。評価器の scope.get を観測し、has による構文確認や依存候補は使用とみなさない。旧変数の出典は成功した代入の後だけ更新する。数値は IEEE-754 round-trip 文字列とし -0 を保持、表示丸め文字列とは分ける。

履歴は最大100回、UTF-8 JSON 500,000バイト。新規追加で超える場合は書込み前に停止し、旧履歴・保存原本・編集内容を維持する。黙った古い履歴の削除は行わない。手動モードで記録候補を作らない通常編集保存と既存履歴の閲覧は可能。旧自動モードでは保存時に計算するため、上限到達後の成功計算の追加保存は拒否する。原本JSON退避後、新しいメモで計算を継続できる。履歴だけの削除UI・自動圧縮は今回対象外。

保存形式のトップレベルversion=1は変更しない。履歴がない旧データはそのまま読み込め、過去使用値は確認不能。未知fieldは既存の保持規則を継続し、履歴の未対応versionや不正構造は非破壊保護対象。保存済み履歴をdraftから置換せず、元noteの履歴へ追記する。

保存は原本の文字列一致を検査し、書込み後に読戻す。対応環境では同一Web Lockを使うアプリ内writerを直列化し、他タブ変更は競合として停止する。localStorageには原子的CASがなく、古いアプリや外部の非協調writerとの完全排他・永続媒体への物理flushは保証しない。保存成功と数値計算成功を混同しない。書込み後の読戻し例外は「保存された可能性がある」不確定結果として扱い、盲目的に再送せず、書込みを停止して再読込確認を促す。保存待ち中は編集/取消/Escapeを停止し、候補は原本世代に結び付ける。未保存候補も100件/500,000バイトで反映を拒否し、以前の候補とdraftを維持する。

Markdown生成は再評価しない。保存記録を現在の保存結果・現在の依存図とは別項として表示する。記録からの明示的な再現検証は既存評価器で数値・実使用元・順序の整合を確認するが、利用者が変更可能なJSONの真正性や数学的証明は保証しない。将来の評価器変更は新方式識別を要し、旧記録との差を改ざんと断定しない。

# AST評価器の責務と測定

## 方針

基点はPR #22をマージした `6f835985e7e53d2f58c89d15bac04352b3bbc5bd`。従来はASTを全体検証した後、後順リストの全ノードで `node.evaluate()` を呼んでいた。この呼出しは子孫を再コンパイル・再評価するため、検証済み値のMapがあっても重複計算していた。

採用したのは既存の `allowedTree` による全体検証と、private `evaluateTree` による後順一回評価の分離。演算子は固定switch、sqrt/absとpi/eも明示的に選択し、mathjsの既存数値関数へ評価済み子値を渡す。任意の関数呼出しは許さない。新しい汎用評価フレームワーク、キャッシュ、依存追加、構文変更は不要と判断した。

構文検証を途中の評価へ混ぜない。禁止構文が右側にあっても先に拒否する。数値評価は従来通り子から左→右、各中間の有限実数を確認してから親のゼロ除算・指数制限を判定する。最大安全値制限は最終結果のみ。符号付きゼロ、表示丸め、保存される内部値、旧%変換を維持する。

## 再現

リポジトリrootでlocked依存を準備し、基点commitを取得した状態で:

```sh
npm test
node scripts/benchmark-ast.mjs 6f835985e7e53d2f58c89d15bac04352b3bbc5bd
```

スクリプトは旧/現行ソースを一時ディレクトリへtranspileして同じformat/mathjsで比較し、finallyで削除する。1000旧式（四則・括弧・%・暗黙乗算）、1000数学式、29境界/エラーを固定生成する。内部値をObject.is（-0を含む）、表示・式・エラー文を完全一致で比較する。結果差分は非ゼロ終了。単体では安全制限の境界と全構文検証優先、エラー順序も固定する。

速度はparse・検証・評価・format全体。100回warmup後、旧/新の測定順を交互にし、200回を7標本、1式あたり中央値を出す。別パスだけで旧mathjsのコンパイル済みノード実行と新Map保存回数を計測する。新評価中に子孫のcompile評価が走ると失敗する。計測コードを本番評価器へ入れない。速度閾値は設けず、機械・Node・負荷で変わる参考値として扱う。

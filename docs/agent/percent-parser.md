# 後置パーセントの解析修正（Issue #19）

## 原因と方式選択

2026-10-21 (JST)、PR #45 merge後main `fdf10ee6ee7453f583f0c6c92d3e2c06b71dfcb6` を基点とした。
従来の `expandPercent` は数値%と「内部に括弧がない括弧式」%を正規表現で反復置換していた。
数字%自身の変換で作った括弧も次の括弧%を妨げる。`.5%` は `5%` だけを書き換え、不正な式になった。

方式を比較した。
- mathjsの元の構文木を利用: 通常構文には適切だが、mathjs15.2.0は `200+10%` を相対加算、`5%2` や `(5%+5%)` を剰余として解析する。ASTがこの時点でアプリと違う意味を持つため、後段の単純なノード置換では既存契約を保持できない。
- 採用: 入力の数値トークンと対応する括弧開始位置を前向きに走査し、%の直前の対象全体を `(対象/100)` にする。生成した括弧を再探索しない。計算エンジンやmathjsパーサーの再実装ではない。

変換後は従来どおりmathjsで解析し、AST全体の許可リスト・深さ/ノード予算を検査した後、既存の後順一回評価を行う。元入力2000文字、括弧深度32、AST256ノード/深度32、中間有限実数、最終安全整数範囲、精度とエラー優先を変えない。%展開で増えるASTノードも予算に含む。字句走査に再帰はなく、出力長は入力に対して線形に増える。eval/Function/compile/evaluateは追加しない。

## 再現実測

旧コードでは次の4式すべてが「式が不完全か、計算できない内容です」。Issueの古いエラー文とは現行共通catchによって異なる。

| 式 | 修正後期待・単体実測 |
|---|---:|
| `((50+50))%` | 1 |
| `(50+(25+25))%` | 1 |
| `(5%+5%)%` | 0.001 |
| `.5%` | 0.005 |

最初の60回帰を旧コードへ追加した時点では12失敗/48成功、修正後60成功。初回修正後の1件は複合式の期待小数リテラルとIEEE754内部値の差だった。期待値を独立した演算 `((5/100+5/100)/100+1)/100` へ訂正し、近似比較や実値丸めで隠さない。
従来のmath-functions/formula-executionの「Issue19はまだ失敗する」テストだけは今回の修正目的に合わせ成功値へ更新。変数/関数等の混在拒否は維持する。

## 既存の曖昧な境界を変えない

- `200+10% = 200.1`。Excel/実機型の相対加算や剰余には変更しない。
- エンジンは従来 `50%% = 0.005` を受け付け、`50%%%` と `(50)%%` を拒否している。曖昧な連続%の境界は変更せず保持。明示的に括弧で囲んだ `(50%)%` は今回の入れ子%修正の対象。キー入力の連続%拒否は別責務で変更しない。
- 通常電卓の `5%2`, `5%(2)`, `(5)%2` は従来の暗黙乗算で0.1。旧変数モードでは暗黙乗算が許可されないため拒否を保持。
- `50.%` は従来拒否であり未完の小数として保持。`.5%` は小数点の後に数字がある完全な小数として今回修正。
- 通常電卓は空白を正規化するが旧変数モードは保持する。`50 %`, `(50) %` は通常電卓で0.5、旧変数モードで従来どおり拒否。今回空白規則を統一しない。
- `%` と変数/関数/定数/累乗が同じ式に現れる制限は解除しない。ID参照、旧変数の評価順序、試算/全体rollback、保存形式には変更を入れない。

- 不正な複数小数点 `1.2.3%` は旧正規表現が `1.(2.3/100)` 相当へ変換し0.023を返す副作用があった。これは有効な十進数ではないため、今回の完全トークン判定では拒否する。正当な既存数式の期待値を緩めるものではない。

## 検証・限界

単体で4再現、負数/ゼロ/小数、深い括弧、内外%と四則の優先、無効位置、禁止構文、予算、URL/history/旧メモ再計算と付随情報を確認する。統合テストでID元の%結果伝播、試算の非破壊性、古い試算拒否、全体rollbackを確認する。既存全テストは別途継続する。
GUIは6条件すべてで4式を通常入力/URL/保存済み単独メモ/旧計算ブロックに通し、読み込みだけの非変更・明示操作・再保存/再読込を確認する。代表PNGや成功trace保存は増やさない。実行済み件数・CI・独立レビューはLOGとPRに記録し、この設計説明をGUI成功証拠と扱わない。

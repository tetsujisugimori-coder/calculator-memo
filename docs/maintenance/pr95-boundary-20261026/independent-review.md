## 静的所見（実行再現と区別）

## 追加P2：後行資料のpoisonで先行重複資料が完全へ戻る（2026-10-26 23:16 JST）
実装担当が追加の組合せ疑義を提示し、独立担当が静的評価・負例追加・再実行を行った。先に記載した18件での阻害なしはその確認範囲に限るものとして保持し、次の新規指摘と修正を追記する。

構造は「正常閉鎖M1 → 外側A → 同ID M2開始 → 早期正規終端 → 内部B → 本来の正規終端」。一意性修正によりM2が開始からEOFまでpoisonされmetadataを持たなくなると、返却range.metadataからIDを集計していた後段処理がM2を数え落とし、先行M1が重複invalidからcompleteへ戻り得る。B漏出は止まっていても、既存の重複ID保護を弱めるためP2と判定した。

### 原因に対応する補正と静的範囲
ID件数を返却rangeではなく、既存parserの厳密なvalid startMetadata一覧から集計する1行補正を再読した。poisonや差分交差によって返却metadataが失われても、観測済みの重複ID事実は失わせない。
- 普通コード内マーカーはblockとして現れず非計数。未知version、不正JSON、余分キー、不正metadata開始も非計数で、IDを推測しない。
- 入れ子でも厳密に有効な開始は構造上の重複として数える。ただし既存poisonを解除せず、終端の推測対応付けにも使用しない。
- 補正は返却status/metadataの無効化だけで、先行M1の範囲を拡張・短縮しない。間の外側Aを保持し、後行M2のみEOF保護を維持する。
- 未知開始を重複数に数えないことと、その後の複数の正規同ID終端による別の「終端曖昧」判定は別問題である。後者を無効化して保護を解除してはならない。
